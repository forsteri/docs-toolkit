# ビジネスプレゼンパターン集

Agentは資料の目的に最も近いパターンをコピーし、事実・判断・数値・担当を置き換えます。スライド枚数を先に固定せず、1枚1メッセージを保てる単位で増減してください。

| パターン | 選ぶ状況 | 必ず残す流れ |
|---|---|---|
| `proposal.md` | 課題に対する施策の承認・予算化 | 課題 → 解決策 → 効果 → 体制 → スケジュール |
| `progress-report.md` | 定例の進捗共有と阻害要因の解消 | サマリー → KPI → リスク → 次アクション |
| `decision.md` | 複数案から1案を選ぶ | 判断基準 → 比較 → 推奨 → 決定事項 |
| `kickoff.md` | 目的・役割・進め方を揃える | 目的 → 成果物 → 体制 → マイルストーン |
| `retrospective.md` | 実績から次回の改善を決める | 目標と結果 → 成功 → 課題 → 改善実験 |

## Agent向け作成手順

1. 対象者が最後に何を理解・判断・実行するかを1文で定義する。
2. 該当パターンをコピーし、見出しを内容に即した結論文へ直す。
3. 図解は`theme/README.md`のpropsスキーマへJSON互換のデータを渡す。
4. 色はコンポーネントが系列色8色を順に割り当てる。Markdown側で色値を指定しない。
5. 不明な数値・担当・期日は推測せず、`要確認`と明示する。
6. `npm run build:patterns`または対象ファイルの`slidev build`でコンパイルする。
7. PDFまたはSPAを全ページ確認し、タイトル折返し、文字切れ、重なりを直す。

## 禁止事項

- 画像やアイコンによる独自の装飾追加
- 任意のブランド色、グラデーション、影をMarkdown側で追加
- 系列色を強調や装飾の目的で使う（色分けの識別だけに使う）
- 1枚に複数の結論を詰め込み、本文を縮小して収める
- 出典・集計条件・基準日を省略した数値の提示
- インタラクションが必要な資料をPDFだけで配布

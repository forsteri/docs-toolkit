# 目的

APIの5xxエラー率がしきい値を超えた場合に、影響範囲を確認し、一次対応とエスカレーションを一貫して実施するための手順です。

# 発動条件

次のいずれかを満たした場合に使用します。

- 5分平均の5xxエラー率が5%を超えた
- ヘルスチェック失敗が3回連続した
- 主要な利用者操作が完了できないと報告された

::: {.danger}
**重大:** データ破損または情報漏えいの可能性がある場合は、復旧操作より先にインシデント責任者へ連絡してください。
:::

# 初動

1. インシデントチャンネルを作成し、開始時刻を記録します。
2. ダッシュボードでエラー率、レイテンシ、リクエスト数を確認します。
3. 直近30分のデプロイと設定変更を確認します。
4. 単一環境か、複数環境に共通する事象かを切り分けます。

::: {.checklist}
**初動チェック**

- [ ] インシデント責任者を決めた
- [ ] 影響開始時刻を記録した
- [ ] 利用者影響を確認した
- [ ] 直近の変更有無を確認した
:::

# 確認コマンド

```powershell
kubectl get pods -n example-api
kubectl logs -n example-api deploy/api --since=15m
```

# 判断

| 状況 | 対応 |
| --- | --- |
| 直近デプロイ後から発生 | 安定版へ切り戻す |
| 特定インスタンスのみ異常 | 対象を切り離して再作成する |
| 外部依存サービスが停止 | 回避策を有効化し、依存先へ連絡する |
| 原因不明で影響が拡大 | インシデントレベルを引き上げる |

# 復旧確認

1. 5xxエラー率が15分間しきい値未満であることを確認します。
2. 主要操作のスモークテストを実施します。
3. 保留中のリクエストやジョブを確認します。
4. 関係者へ復旧を連絡します。

# 外部プロジェクトからの文書生成 — Phase 0の記入例

これはdocs-toolkitの導入PoCを題材にした、Brief・チェックポイント・検証記録を1つのMarkdownへまとめる例である。利用対象は公開可能な検証用サンプルであり、実案件での利用実績ではない。実際の実行結果は、証拠が揃った項目だけに記載する。

状態: 技術検証の結果を記録済み。方式・文書の型ともに人間の採用判断前。
正本: [Issue #1](https://github.com/forsteri/docs-toolkit/issues/1)、[Issue #2](https://github.com/forsteri/docs-toolkit/issues/2)、[ROADMAP.md](../../ROADMAP.md)。

## チェックポイント

### 1. 判断してほしいこと

**共通cloneの固定SHA参照とPandoc単体HTMLを、Issue #3の最小利用導線へ進める暫定方式にするか。この3役割を統合したMarkdownを最初の文書の型にするか。**

選択肢は、この範囲で続行、条件を修正して再試行、保留。推奨は、固定SHAの共通clone参照とPandoc単体HTML、3役割を統合したMarkdownで、小さくIssue #3へ進めること。固定版の再取得、外部資産の埋め込み、切替・撤回を実行でき、利用側本文とツールキットを変更せずに検証できたためである。人間による実物の確認と採用判断は残っている。

続行した場合も、取得方式と実行インターフェースは別に扱う。汎用CLIやパッケージ化の採用を、このPoCの方式選択に含めない。

## Brief

### 課題と目的

現状: 既存のツールキットには形式別の同梱サンプルとスクリプトがあるが、外部利用の取得方法と原本・資産・生成物の境界は比較・検証が必要である。目的や判断材料の文書の型も、最小セットを試して確認する必要がある。根拠はIssue #1・#2とROADMAP.mdを正本とする。

目的: 初期利用者とコーディングエージェントが、小さな変更の目的を揃え、外部原本から作った実物をレビューし、次の範囲へ進むかを判断できる状態にする。

### 対象・対象外

対象: 4つの取得方式の比較、少なくとも1案の外部利用PoC、再実行方法と検証記録、Brief・チェックポイント・検証記録の雛形と記入例。

対象外: Issue #3以降の本実装、全形式・全OS対応、新しい配信サービスや常駐基盤、実案件やグローバル設定の変更、人間による採用判断の代行。

前提・制約: 第一の対象はmacOSローカル。Markdown中心でブラウザ閲覧を優先する。公開可能なサンプルだけを使い、検証用プロジェクトはツールキットの作業ツリー外へ置く。この条件は今回の試行を定め、将来の全利用条件を固定しない。

### この記入例をブラウザで確認する

このファイルは、雛形の使い方を示す記入例である。以下は、この記入例自身を既存PandocテンプレートでHTMLにする手順であり、外部利用PoCの検証とは区別する。リポジトリ直下から実行する。Pandoc 3.xが必要で、生成物はGit追跡対象外の `output/` へ置く。

```bash
mkdir -p output/phase0
(
  cd pandoc
  pandoc --defaults defaults/html.yaml --fail-if-warnings \
    --metadata title='Phase 0 の記入例' \
    ../examples/phase0/review.md -o ../output/phase0/review.html
)
```

`output/phase0/review.html` をブラウザで開き、チェックポイントの先頭4項目と、Brief・実行証拠への参照を確認する。リンク先のMarkdownは原本を示しており、単体HTMLと一緒に資料一式を持ち出すための配布処理は、この例には含めない。

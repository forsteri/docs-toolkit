## 目的

対象事象と、このランブックで実施できる対応範囲を記述します。

## 発動条件

- アラート名としきい値
- 利用者から報告される代表的な症状
- このランブックを使用しない条件

:::danger[重大]
データ破損、情報漏えい、広範囲な停止の可能性がある場合に、最初に実施する連絡と保全操作を記述します。
:::

## 初動

1. インシデントの開始時刻を記録します。
2. 影響範囲と重要度を確認します。
3. 直近のデプロイと設定変更を確認します。
4. 責任者と連絡先を確定します。

## 確認項目

- [ ] エラー率、レイテンシ、リクエスト数
- [ ] 対象環境、リージョン、テナント
- [ ] 直近の変更
- [ ] 外部依存サービスの状態
- [ ] ログの代表的なエラー

## 確認コマンド

コマンドを実行する環境、必要な権限、期待結果を併記します。

```bash
kubectl get pods -n example
kubectl logs -n example deploy/api --since=15m
```

## 判断と対応

| 状況 | 対応 | 判断者 |
| --- | --- | --- |
| 直近変更が原因 | 安定版へ切り戻す |  |
| 単一インスタンスのみ異常 | 切り離して再作成する |  |
| 外部依存が停止 | 回避策を有効化する |  |
| 原因不明で影響拡大 | 重要度を引き上げる |  |

## 復旧確認

1. 主要メトリクスが一定時間正常であることを確認します。
2. 利用者の主要操作を確認します。
3. 保留中の処理とデータ整合性を確認します。
4. 関係者へ復旧を連絡します。

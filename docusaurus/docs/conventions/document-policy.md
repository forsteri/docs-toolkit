## 出力形式の使い分け

| 条件 | 推奨形式 |
| --- | --- |
| 複数ページを継続更新し、ナビゲーションで参照する | Docusaurus |
| 単体HTMLまたはPDFとして配布・保管する | Pandoc |
| 概念・方針・構成・ロードマップを1枚で説明し、画面共有する | One-pager |
| 発表用のスライドを作る | Marp / Slidev |

PandocとDocusaurusはニュートラルな技術文書スタイルを使用します。One-pagerも同じ配色ですが、文字を大きく、部品を少なく限定した1枚資料の形式で、1枚に収まらない内容は扱いません。スライド向けの`forsteri`テーマ（見出し帯・章扉・系列色などのブランド表現）はMarpとSlidevで使い、文書系とは主色のティールだけを共有します。

## 文書タイプ

### 設計書

実装とレビューに必要な判断材料をまとめます。目的、スコープ、要求、方式、インターフェース、データ、失敗時の挙動、運用、リスクを扱います。

### 手順書

作業者が迷わず実施でき、確認者が完了を判断できる粒度で書きます。開始条件、操作、期待結果、切り戻し、作業記録を扱います。

### 判断記録

一つの重要な判断を短い文書として残します。決定、背景、判断基準、比較した選択肢、影響、見直し条件を扱います。

### 運用ランブック

アラートや事象から、切り分け、一次対応、復旧確認、エスカレーションへ進むための実務情報をまとめます。

## メタデータ

すべての文書で、必要な範囲のメタデータを持たせます。

| 項目 | 用途 | 例 |
| --- | --- | --- |
| 文書ID | 一意な識別 | `DESIGN-AUTH-001` |
| ステータス | レビュー状態 | `Draft`, `Review`, `Approved`, `Deprecated` |
| バージョン | 配布版の識別 | `1.2.0` |
| 最終更新 | 情報鮮度の判断 | `2026-08-13` |
| オーナー | 更新責任 | `forsteri` |
| 分類 | 共有範囲 | `Internal` |

## ライフサイクル

1. `Draft`で作成します。
2. 読み手または実施者の観点でレビューします。
3. 承認後に`Approved`へ変更します。
4. 内容が置き換わった場合は、後継文書へのリンクを示して`Deprecated`にします。

:::warning[古い手順の扱い]
廃止した手順書やランブックを削除するだけにしないでください。誤参照を防ぐため、廃止理由と後継文書を明示します。
:::
